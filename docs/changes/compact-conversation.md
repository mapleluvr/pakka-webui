# 紧凑对话阅读与输入

工具密集的对话中，正文和 Commentary 始终按消息内容的原顺序显示。相邻活动收成一行，按需展开为有序清单，再查看单次调用的参数与输出，或单段 Thinking。进行中与完成摘要都省略零计数，例如 `Running (1 tool call, read)` 或 `Done (2 tool calls)`，失败仍有单独提示。搜索已载入的预览时显示命中的组与条目。已有的原文引用决定可读范围。空的 Thinking 在没有后续可读原文时不参与展开和计数。有结构化命令的 shell 调用直接显示命令；输出、退出提示和其他参数分区显示，标题栏的复制与搜索针对该块。命令的原文入口明确标为参数原文，可核对完整参数 JSON。归档的 PowerShell 字段装饰与标准退出提示可在预览中简化显示；保存的原文仍可逐字核对。

工具失败与模型生成失败分别计数。同一组运行中的错误按结果到达顺序更新 `<action>`；Done、Failed、Stopped 只显示非零计数，发生过错误的组保留 `Needs attention!`。单独模型错误以「回复失败」卡呈现。服务商、已知 HTTP 状态、结构化错误码以及工具名与退出码限定匹配范围；相邻记录在去除请求 ID、前缀、词集合或字形相似度命中时折成 ×N。每次保留原文与其自身的操作。用户输入、正文或来源切换划分边界，摘要使用当页可见记录；观察或刷新同一页不会增加次数。服务商 / SDK 内部没有逐次上报的重试不计入。普通回答中引用的错误文字仍属于回答。

`codemode` 采用 pi-pretty-tui 的脚本与脚本输出独立开合。输入使用公开 `arguments.code`；有匹配的 Pi 结果头时，按实际返回顺序显示耗时、编号文本、console、图片与失败时保留的部分输出。含糊或截断的文本保留原预览。文本内部的小节共享其所属结果片段的原文操作。pi-pretty-tui 使用原生执行事件 `parentToolCallId` 和调用快照归属子节点；当前 Pocket 记录只提供顶层调用与其输出，浏览器不推算子调用、不读取插件隐藏条目。

能以本人回执唯一绑定的用户消息标为「你」。已答复的消息保持安静；实时观察中已纳入运行的输入显示「处理中」和转环，减少动态效果时使用静态图标。输入状态可从「我的输入」查看或刷新；「到本页最新消息」控制阅读位置。「会话标识」展开 Session 与 Conversation ID，「刷新对话记录」重新读取当前页。两组操作共享字号、点击区域与 SVG 线条样式。

发送方式说明在选择菜单中显示；收起后按钮用「发送消息」「发送补充」「发送跟进」指示当前选择，三种状态共享宽度，保持输入区和阅读边界稳定。

输入控件集中在草稿下方；窄屏使用短模型名，完整模型仍可通过模型选择查看。桌面用户可以调整导航宽度和草稿高度，键盘方向键微调，Enter 或双击恢复默认。手机使用单独的默认尺寸。工作台把个人文件夹管理放入每行尾部菜单，表单的焦点指示沿实际输入外框显示。
