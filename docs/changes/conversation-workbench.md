# Conversation 工作台：阅读、输入与原文模式

## 采用来路

用户授权在功能与交付风险收敛后使用 design-companion 调优界面，并开放 layout、元件/组件与视觉语言的重新设计。权限、完整原引用、持久请求和插件归属继续沿已采用的契约。

初次代码试稿将已打开页面移入侧栏，历史独立滚动，输入置于下部。真实页面显示输入区仍偏高，模型/Thinking/配置与听写随后收进紧凑工具栏，回执清单与阅读导航组合成独立状态栏。候选中 UUID 的位置及“我的输入”归属也在代码中重新安排。

连续阅读暴露了两个问题：发送完成后新回复没有接续可见；配置刷新重建阅读实例，又把此前发送标记当成新发送。现采用明确发送接续、手动交互暂停、同一范围保留实例的方式。

消息动作合入 header 后，长原文的读取虽然成功，搜索与返回仍会离开可视范围。现采用同一视图一次选取一条原文、各条保留控制位置、固定返回入口与同行搜索控件；消息预览和原文分别呈现。发送新消息进入新回复阅读，配置或查询旧请求保持当前阅读意图。

刷新恢复还发现普通输入仅有原 requestId 可见。现从持久待核对记录初始化正文和 mode，原消息详情保留冻结参数；核对成功只清除对应原请求，并保留后来另写的草稿。

最终差异核对补验了正常发送期间的编辑：安装版留住已接纳响应，继续输入新草稿，再释放响应，复现了原成功处理无条件清空输入框。现让正常发送与原请求核对沿用相同的正文比对，只清空仍对应本次提交的内容。固定前端重打后，两次响应等待与一笔 390px 正常输入分别核对，各只产生一次 Provider 请求；刷新和配置窗撤权清理通过。初轮缺少错误监听的覆盖限制及完整监听补验分别记录。

## 当前分工

壳层与页面导航由 `src/app` 维护；Conversation 的窗口、控制位置、正文与输入仍按实际职责组合。公开服务/client 和持久回执契约保持各自所有者。布局用临时真实页面探针检验，沿本阶段少测试规则保留界面开放性；安全与持久效果继续由已有服务回归保护。

采用后的声明见 [WebUI state](../state/webui.md)，实测与未覆盖条件见[工作台界面核对](../verification/WORKBENCH-INTERFACE.md)。主界面与阶段 4 固定候选在当时完成局部验证，阶段退出受回归失败阻塞。随后[阶段 5](../verification/PHASE-5.md)按逐项覆盖接续旧检查、补齐命令/重开缺口并完成默认安装；真实录音因本机无设备获用户授权跳过，识别质量保留未验证。
