# 工作台与插件的应用内反馈

工作台创建个人文件夹曾显示「已核对原操作结果」，而输入框下的「本次提交：已接纳」在开始写下一条时仍留在原处。现在由短通知说明刚刚得到的回执，由页面保留对象、当前状态与仍可执行的查询。

沿用 `UiContext.notice → registry → Application`，未增加平行通知服务。registry 负责有效实例、可见容量、合并与撤销；更新事件与卡片身份分开，使旧的到期或清理不能误删更新。命令临时实例可在正常结束前发布反馈；调用方或插件撤销时清理所属提示。窄屏淘汰旧卡，而不是只用 CSS 隐藏待播项。展示层采用静态主题 CSS、SVG 和原生按钮，直接呈现 registry 的可见项，不另建 Astryx Toast 队列。弹窗中移动同一展示容器，不新建另一套卡片或计时器。

个人工作台按确认的操作与提交时的目标名称说明结果；显示用名称不进入服务查询。对话区区分输入排队、送达和执行，原回执能唯一定位本人消息的 Entry 时原位标注。响应丢失仍按同一目标、模式、正文与请求身份查询；未知时保留恢复入口，不以通知消失、清单刷新或开始新草稿作为完成依据。已正常连接的实时对话不再常驻显示两条连接标签。

本地用独立构建、公开 SDK、隔离 Pakka 和回环确定性模型核对，包含创建文件夹、丢失重命名和消息响应、查询为空后再次查询、保留后写草稿、排队和复制。桌面和 390px 浏览器检查覆盖折叠、计时、手势、弹窗、主题与 reduced motion。固定产品归档、Provider 配置、个人文件夹布局和系统推送均未改动。
