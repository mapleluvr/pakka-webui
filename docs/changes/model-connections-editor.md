# 提供商与模型：实例设置编辑器

在设置中，新端点从「新建提供商」开始：给出提供商 ID、聊天协议、服务端点和首个模型的完整 ID，再校验或保存。已有内置或扩展模型只换端点时，从「覆盖已有提供商」开始，仅设置 `baseUrl`。`localhost` 是 Pakka 所在机器；个人默认模型、对话选用的模型和已存认证不会随表单切换。

提供商设置的「模型参数配置」列出完整模型 ID；仅当定义和覆盖共用 ID 时，才按「模型定义」和「目录模型覆盖」分组。「添加模型定义」创建 `models[]` 条目；「覆盖目录模型」只从该提供商的已加载 chat 模型选择完整 ID，写 `modelOverrides`。配置中已有、当前目录未找到的覆盖仍可查阅。API 建议来自 Pi 1.4.0 的已知聊天协议和当前目录查询；其他 ID 可手工输入。已选的已知协议显示为 `OpenAI Responses (openai-responses)` 等名称与 ID；其他协议只显示 ID。

- 兼容项按准确协议分组。「提供商兼容性设置」的「按协议查看」筛选与「新增模型的默认协议」是两件事。改协议不会删除此前的 compat。未知、不适用或复杂的原生项仍可从高级入口查看。
- 提供商和模型兼容性、Thinking Levels、Sampling Params 与原生参数使用固定的折叠标题，显式值在对应字段显示，受保护路径在所属参数层标识。
- Thinking 的支持开关与映射分开。映射表逐行对应 Pi 级别和提供商请求值，可直接填写任意非空请求值；清空删除本层键，勾选「禁用此级别」显式写 `null`。取消禁用恢复继承，也可以直接输入新值。关闭支持不擦除映射。Sampling Params 分模型默认与按级别覆盖；区分数值、布尔、文本、null 和单值 JSON。只有确认合入采样请求体的 Completions、Responses 和 Azure Responses 三个精确 API 标作适用。
- 每份草稿定位到提供商、模型完整 ID 和原文版本；恢复继承是可撤下的叶子移除。校验不发布文件。保存先离线校验，写前保留原请求；失去回执只能核对，不换身份重发。另行重载不会重新写文件。「原生参数」用 Astryx TreeList 保留父项和同级的本层值；键盘方向键浏览，Enter 激活。宽详情在树旁改值；窄详情打开底部面板，关闭时保留输入与展开状态，焦点回到树。常规表单能表达的叶子不重复编辑；其余公开子参数按原路径进入。树头添加根项，展开行末添加直接子项。键中的点、空格或斜杠不拆分，准备空分组不写配置。合法值直接加入对象草稿，未完成的数字或数组标为待修正并阻止整体保存。新增、更改与移除可分别撤销；浏览和展开不产生草稿。
- 宿主管理项不预填：提供商自身字段与所属模型字段分开；模型级管理项按字段折叠，计数按可确认的模型 ID 去重，同名定义和覆盖注明归属。提供商自身的 `headers` 行下方用「覆盖以上请求头设置的模型」列出另外设置了模型级 `headers` 的完整 ID；没有该上层字段时用「单独设置了请求头的模型」。不推断任一请求头键或值。模型页面只列自身管理项，数组仅在完整公开时才作单值编辑。含受保护子项的对象可进入修改公开兄弟键，但不能整组复制、覆盖或删除。受保护值、请求头和认证 URL 不进入原请求记录。

范围仅为独立前端。宿主负责授权、原子文件发布、脱敏与目录；编辑器不发送推理、探测、模型登录或目录网络刷新。协议/适配器语义按此处所用的 Pi 版本维护，不把目录读取或离线校验当作请求包验证。
